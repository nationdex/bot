# Contributing and Volunteering

My gratitude to those who seek to contribute and volunteer themselves for Project Nationdex 2026 (Nationdex 2.0) is incredibly immense, and you have no idea how much it flatters my heart to see Nationdex being valued by you at some point. Thank you for your dedicated assistance to make the dex community blue and united again.

Now, allow us to inform you about the requirements to operate on the Project Nationdex 2026 (Nationdex 2.0) and assist on its development.

## Prerequisites

Before anything, please make sure to install Node.js through its [website](https://nodejs.org/), and then, follow the instructions from the [readme](https://github.com/nationdex/bot#readme), in order to setup the codebase and test it on your environment.

## Recommended IDEs

- Visual Studio Code

> VS Code is the main IDE anyway, nothing can escape the almighty Microsoft.

- Antigravity

> If you want an AI-driven IDE by your side to do a lot of hallucinations on the ForgeScript codes and make you suffer in the process, then use Antigravity lol.

## Recommended Extensions

- ForgeLSP/ForgeVSC

> THIS IS IMPORTANT SIR! Both ForgeLSP and ForgeVSC gives ForgeScript an actual type-safe layer on the codebase, making it easier to develop and maintain.

- NPM Intellisense

> This extension is for you to import modules and stuff with ease, without causing you a headache or whatever.

## Important Note

Linting and formatting is not needed for the codebase, since ForgeScript codes could end up being ruined by the formatter, causing the bot to break. Therefore, it is recommended to only use linting and formatting checks on the admin panel code instead of the root ForgeScript files. However, you are always recommended to run typecheck solutions across the codebase to check for any issues.

## Pull Requests and Issues

In a large-scale project such as Project Nationdex 2026, you are always encouraged to create a fork and contribute to the codebase whenever necessary or whenever you dislike something on the project, but let's not forget that if you do not have any programming knowledge, you can always voice your criticisms and inputs on the Issues tab of our repository.

> **One thing to clarify**, we do NOT tolerate any blind or straight up invalid criticism towards the project, even if you're a developer or whatever. Make sure you review the codebase and understand how the structure works, together with the stack used on it, before giving any input or opinion.
